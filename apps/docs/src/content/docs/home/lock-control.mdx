# Lock Control

<Lead>Lock or unlock a door, and ask before unlocking.</Lead>

## When to use it

Use it in a lock's control sheet. It shows HomeKit's four lock states (locked, unlocked, jammed and unknown) and what the lock is doing while it moves.

- Unlocking asks first. The HIG asks you to require authentication for actions that affect security, like unlocking the door to a house; a native app would also check Face ID or the passcode. Locking never asks.
- Pass `target` as soon as someone presses it, and `state` when the lock reports back. While they differ, the control says "Locking…" or "Unlocking…".
- When a lock reports jammed, say so. The control turns yellow and reads "Jammed"; pressing it tries to lock again.

## Usage

```tsx
import { LockControl } from "macbetter/lock-control"
```

## Platform behavior

- **iOS and iPadOS.** A 124 × 240-point button with a continuous corner, and a confirmation alert.
- **macOS.** 88 × 168 points, sized for a popover; the confirmation is a Mac alert.
- **Every platform.** Unlocked is the bright look, like a lit accessory tile: it's the state that wants attention. The shackle lifts when unlocked.

## Accessibility

- The button is named for what it does, "Unlock Front door", and the state under it is a live region, so screen readers hear "Unlocking…" and then "Unlocked".
- Enter or Space presses it. The alert takes focus, Escape cancels, and focus returns to the button.
- State is in words and in the glyph's shape, not only in color.

### Data attributes

| Attribute | On | Values |
| --- | --- | --- |
| `data-state` | Root | `secured`, `unsecured`, `jammed`, `unknown` |
| `data-position` | Root | `locked`, `unlocked`: where it is, or is going |
| `data-pending` | Root | Present while locking or unlocking |
