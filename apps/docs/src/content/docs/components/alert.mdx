# Alert

## When to use it

Use an alert when someone has to decide before anything else can happen: confirming something that can’t be undone, or choosing what happens to unsaved work. Alerts interrupt, so keep them rare. Don’t use one to report that something went well; a [Notification](/docs/components/toast) or an inline status does that without stopping anyone.

- Write the title as the question (“Delete this photo?”), and use the message for the consequence, in a sentence or two.
- Label buttons with verbs that answer the question (“Empty Trash”, “Don’t Save”), never “Yes” and “No”.
- Mark the action people usually want as `primary`. When the action destroys something, give it `tone="destructive"`, and consider making Cancel the default instead.

## Usage

```tsx
import {
  Alert,
  AlertAction,
  AlertActions,
  AlertContent,
  AlertDescription,
  AlertIcon,
  AlertTitle,
  AlertTrigger,
} from "macbetter/alert"
```

`AlertContent` brings its own dimmed backdrop. `AlertAction` closes the alert and reports its `value`; `value="confirm"` is the agreeing answer that `createConfirm()` resolves `true` for. Put the least destructive action first in the markup, since the alert opens with focus on it.

Mark an action that destroys something with `data-agent-confirm`, so an AI agent driving the page has to ask the person before it presses it.

### Three choices

Two actions sit side by side; three or more stack, with the `cancel` action at the bottom. Set `orientation` on `AlertActions` to force either layout.

<Demo name="alert/stacked" wallpaper height={420} />

### Action sheet

On iPhone, a destructive choice that follows a tap usually rises from the bottom as an action sheet. Pass `variant="sheet"` to `AlertContent`: the choices sit in one card and Cancel stands apart below it. On the Mac and iPad the same markup shows a regular alert.

<Demo name="alert/action-sheet" platforms={["ios"]} wallpaper height={420} />

### Asking from code

Create a confirm function with `createConfirm()`, pass its `controller` to an `Alert`, and `await` the answer from any handler. It resolves `true` when the `value="confirm"` action closes the alert.

```tsx
const [confirmDelete] = useState(() => createConfirm<{ name: string }>())

async function remove(name: string) {
  if (await confirmDelete({ name })) deleteProject(name)
}

<Alert controller={confirmDelete.controller}>
  <AlertContent<{ name: string }>>
    {(state) => (
      <>
        <AlertTitle>Delete “{state.payload?.name}”?</AlertTitle>
        <AlertActions>
          <AlertAction variant="cancel">Cancel</AlertAction>
          <AlertAction tone="destructive" value="confirm">Delete</AlertAction>
        </AlertActions>
      </>
    )}
  </AlertContent>
</Alert>
```

## Platform behavior

- **macOS.** A 260pt panel of thick material with the app icon on top, a bold 13pt title and an 11pt message. Buttons are full width; the primary one is filled with the accent. It scales in from slightly smaller, without a bounce.
- **iOS and iPadOS.** The 270pt alert: no icon, a 17pt semibold title, a 13pt message and full-bleed text buttons divided by hairlines. The primary action is bold and destructive ones are red. It settles in from slightly larger, as the system alert does.
- **Action sheet.** iPhone only. On iPad, where an action sheet would be a popover, and on the Mac, `variant="sheet"` shows the alert.
- iOS and iPadOS dim the page with the scrim. macOS doesn’t dim the window behind an alert, so the Mac gets a lighter veil, just enough to show the page is blocked. The alert’s material is denser than a menu’s so the message reads over any backdrop. Reduced motion drops the scale; reduced transparency makes the material opaque.

## Accessibility

- The alert has the `alertdialog` role, is named by its title and described by its message.
- It opens with focus on the first action, keeps Tab inside, and makes the rest of the page inert. Pressing outside never closes it.
- Escape closes it and returns focus to the trigger, like Cancel.
- In a stack, the cancel action moves to the bottom visually but keeps its place in the Tab order, first.

`AlertTrigger`, `AlertTitle`, `AlertDescription` and `AlertIcon` take their element’s props. `createConfirm`, `confirm` and `createAlertDialogController` are re-exported from ui-sdk.

| Data attribute | On | Meaning |
| --- | --- | --- |
| `data-variant` | `.mb-alert` | `alert` or `sheet` |
| `data-orientation` | `.mb-alert-actions` | The layout you asked for |
| `data-variant`, `data-tone` | `.mb-alert-action` | Its role and color |
| `data-starting-style`, `data-ending-style` | `.mb-alert`, `.mb-alert-backdrop` | Entering and leaving |
| `data-pending` | `.mb-alert-action` | Its action is running |

| CSS variable | Default |
| --- | --- |
| `--mb-alert-width` | 260px on macOS, 270px on iOS and iPadOS |
| `--mb-alert-radius` | `--mb-popup-radius` on macOS, 14pt on touch |
| `--mb-alert-enter-scale` | 0.92 on macOS, 1.12 on touch |
| `--mb-alert-scrim` | A lighter `--mb-scrim` on macOS, `--mb-scrim` on touch |
