## When to use it

The menu bar is where people look for any command on the Mac, so every action your app offers should be reachable from it. Use it for a full desktop app; a single page or a phone layout doesn't need one.

- Start with the app menu, titled with the app's name, then File, Edit, View, any app-specific menus, Window and Help, in that order.
- Keep the menus and their items stable. Disable an item that doesn't apply instead of hiding it.
- Give every frequently used command a keyboard shortcut and follow the standard ones (⌘N, ⌘S, ⌘Z).

## Usage

```tsx
import { MenuBar, MenuBarContent, MenuBarTrigger } from "macbetter/menu-bar"
import { Menu, MenuItem } from "macbetter/menu"
```

Put one `Menu` per title inside `MenuBar`, with a `MenuBarTrigger` and a `MenuBarContent`. Mark the app menu's trigger `app` to set it in bold. The items are the [Menu](/docs/components/menu) parts.

## Platform behavior

- **macOS**: a 24-point translucent bar with 13-point titles. The open title gets a rounded fill, and its menu hangs straight from the bar without scaling. With one menu open, moving the pointer across the bar opens each menu in turn.
- **iPadOS**: the menu bar people pull down from the top of the screen, with taller titles, capsule highlights and iPad-sized menus.
- **iOS**: there's no menu bar. Put the commands in toolbars and pull-down buttons.

## Accessibility

The bar is one tab stop with `role="menubar"`; name it with `aria-label`. Left and Right move between titles, Down or Enter opens a menu, Left and Right in an open menu move to the next one, and Escape closes it and returns focus to its title.
