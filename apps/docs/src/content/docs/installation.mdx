# Installation

<Lead>Add macbetter to a React app in four steps. You need React 19 or newer.</Lead>

<Steps>

### Install the packages

macbetter's components wrap ui-sdk's, so install ui-sdk next to it. Installing both packages yourself keeps one copy of ui-sdk's core in your app.

```bash
pnpm add macbetter @ui-sdk/react @ui-sdk/core
```

### Import the stylesheet

Import `macbetter/styles.css` once, in your global stylesheet. Everything in it sits in a cascade layer named `macbetter`, so any rule you write outside a layer wins without `!important`.

Declare the layer order at the top of the file. ui-sdk's layer comes first and macbetter's sits above it. If you use Tailwind CSS v4, list Tailwind's layers around them and import Tailwind before macbetter, as this site does:

```css title="app/globals.css"
@layer ui-sdk, theme, base, macbetter, components, utilities;

@import "tailwindcss";
@import "macbetter/styles.css";
```

With that order, Tailwind's utilities override macbetter's component styles, and macbetter's tokens override Tailwind's preflight. Without Tailwind, the first line is just:

```css
@layer ui-sdk, macbetter;
```

### Set the platform and theme

Render `<MacbetterScript />` at the top of `<body>` in your root layout. It's a small inline script that sets `data-platform` on `<html>` before the page paints: `macos` for a fine pointer, and `ios` or `ipados` for touch, split at 744px wide.

Put `data-theme` on `<html>` to choose a theme, and `data-macbetter` on `<body>` to give the page macbetter's background, text color and font.

```tsx title="app/layout.tsx"
import { MacbetterScript } from "macbetter"
import "./globals.css"

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en" data-theme="ember" suppressHydrationWarning>
      <body data-macbetter="">
        <MacbetterScript />
        {children}
      </body>
    </html>
  )
}
```

`suppressHydrationWarning` is there because the script changes an attribute on `<html>` before React hydrates.

Colors follow the system's light or dark setting. To pin one, add `data-scheme="light"` or `data-scheme="dark"` to any element. ui-sdk's `createColorScheme` writes `data-color-scheme`, which macbetter reads the same way.

### Use a component

Import each component from its own entry.

```tsx
import { Button } from "macbetter/button"
import { Switch } from "macbetter/switch"

export function Example() {
  return (
    <>
      <label>
        Wi-Fi
        <Switch defaultChecked />
      </label>
      <Button variant="filled">Join network</Button>
    </>
  )
}
```

</Steps>

## Next.js

macbetter is published as compiled JavaScript with type declarations, so Next.js needs no extra configuration. Each component is its own file and keeps its `"use client"` directive, so you can import components straight into Server Components.

### Render elements in client components

Some parts take an element through `render`, such as a button that renders as a link. Create that element in a client component:

```tsx
"use client"

import { Button } from "macbetter/button"
import Link from "next/link"

export function DocsLink() {
  return <Button render={<Link href="/docs" />}>Read the docs</Button>
}
```

An element created in a Server Component can reach the browser before React has resolved it. ui-sdk reads it straight away, so it throws "Element type is invalid". It depends on timing, which makes it easy to miss in development.

## Vite and other client-rendered apps

In an app that React renders in the browser, like a Vite app, the browser doesn't run a script that React inserts. `MacbetterScript` still works there: it sets `data-platform` when it mounts. That is one frame later than a server-rendered page, so a phone can paint with Mac metrics for a moment.

To set the platform before first paint, put the same script in `index.html`, above your bundle. `platformScript()` returns it as a string, with the same `platform` and `storageKey` options:

```html title="index.html"
<script>
  ;(() => {
    const coarse = matchMedia("(pointer: coarse)").matches
    document.documentElement.dataset.platform = coarse
      ? matchMedia("(min-width: 744px)").matches ? "ipados" : "ios"
      : "macos"
  })()
</script>
```

```ts title="vite.config.ts"
import { platformScript } from "macbetter"
import { defineConfig } from "vite"

export default defineConfig({
  plugins: [
    {
      name: "macbetter-platform",
      transformIndexHtml: () => [{ tag: "script", children: platformScript(), injectTo: "head-prepend" }],
    },
  ],
})
```

Use either one. With a client-side router, pass its link to components through `render`, for example `<SidebarItem render={<Link to="/inbox" />}>`.

## Import only the styles you use

`macbetter/styles.css` holds every component. To ship less CSS, import the foundation and then one stylesheet per component, in the same layers the full stylesheet uses:

```css title="globals.css"
@layer ui-sdk, macbetter;

@import "macbetter/styles/tokens.css" layer(macbetter.tokens);
@import "macbetter/styles/platforms.css" layer(macbetter.tokens);
@import "macbetter/styles/themes/ember.css" layer(macbetter.themes);
@import "macbetter/styles/base.css" layer(macbetter.base);
@import "macbetter/styles/materials.css" layer(macbetter.base);

@import "macbetter/styles/components/button.css" layer(macbetter.components);
@import "macbetter/styles/components/menu.css" layer(macbetter.components);
@import "macbetter/styles/components/select.css" layer(macbetter.components);
```

Keep that order: tokens, themes, base, then components. The order among component files doesn't matter.

A component's stylesheet has the same name as its entry: `macbetter/select` needs `select.css`. Some components are drawn with another component's classes, so they need its stylesheet too. Select's popup uses `menu.css`, for example. These are the ones that do:

## Imports

| Import | What it gives you |
| --- | --- |
| `macbetter/<component>` | One component and its parts, like `macbetter/segmented-control` |
| `macbetter` | Every component, plus `MacbetterScript`, `platformScript`, `resolvePlatform`, `cx` and the theme helpers |
| `macbetter/styles.css` | The whole stylesheet: tokens, platforms, themes, base, materials and components |
| `macbetter/themes/<name>.css` | One built-in theme's stylesheet on its own |
| `macbetter/styles/<path>` | One file of the stylesheet, like `macbetter/styles/components/button.css` |
| `macbetter/theme` | `createTheme`, `themeVariables`, `contrastRatio` and their types |

Prefer the per-component entries in app code: they make it obvious what a file uses.
